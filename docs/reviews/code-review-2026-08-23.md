The thesis of the first version survives and is strengthened. The recurring shape is not carelessness — the code inside the gates is genuinely strong, and the auth, tenant-isolation and injection posture verified clean twice, independently. It is that **an annotation keeps standing in for a control**, and the annotation is what stops anyone looking. The Python tree holds the starkest instance: **261 `noqa` suppressions across 121 files, naming 12 ruff rule codes, for a linter configured nowhere.** Several carry careful hand-written justifications. Five of the codes are the security and blind-except rulesets. Every one was inert. `trust_ceiling.py`'s parity comment, `sticky_stop.py`'s inert arms, `holds.ts`'s phantom cron, `conformance.ts`'s undefined function, `knip.jsonc`'s "reported but non-blocking", and `safety-substrate/README.md`'s "same enforcement code paths" are the same defect six more times.

### 2. Security

**Recovered findings first.** The two below came from the dedicated security agent whose report never reached the orchestrator. Both were re-verified line by line before being recorded here.

1. [HIGH — FIXED 2026-08-24] **The booking manage token was written into the `events` analytics table.** `/book/manage/<token>` carries the token as a **path segment**, and that token *is* the auth: `api/booking/manage/[token].ts:11` states "The token itself IS the auth — no session required", and the route returns `guest_name`/`guest_email` and grants cancel and reschedule. `lib/booking/tokens.ts:18` states the raw token is "never written to the DB or logged." Three things had to hold and all three did: `Base.astro:63` rendered `<EventsTracker />` **unconditionally**, outside the `!disableAnalytics` guard its two siblings sit behind — while the manage page *already passed* `disableAnalytics`, so the author had done the right thing and one of three trackers ignored it; the tracker posts `location.pathname`; and `scrubPath`, on both the client (`EventsTracker.astro:85`) and the server (`events.ts:196`), stripped only `?` and `#`. `MAX_PATH_LEN` is 512, comfortably fitting the 43-char token. Fixed in commit `670c049e`: the tracker now honours `disableAnalytics`, and both `scrubPath` implementations redact credential-shaped path segments — an explicit prefix list plus a generic 24-char url-safe-base64 guard, so a future token-bearing route is covered without anyone remembering. **Historical rows: CLEAR, probed 2026-08-24** (`vfy_01M0T6N77R261RYNM4H963XT2N`). Production D1 holds **0** rows matching `/book/manage/%` in `path` and **0** whose `metadata` contains `manage` or `token` — against a populated table (269 rows, 21 distinct paths, **14 of them `/book%`**), so the query could have returned non-zero and did not. Nobody has ever opened a manage link, so no token was ever written. No purge or rotation is needed. The defect was live and reachable; the exposure was zero.
2. [HIGH] **No security response headers anywhere in the repository.** A case-insensitive search for `content-security-policy|x-frame-options|strict-transport-security|frame-ancestors` across all `.ts/.astro/.mjs/.toml/.json/.js` returns **zero** matches; there is no `public/_headers`, and no ADR defers them. `admin.smd.services` and `portal.smd.services` are therefore framable, with no clickjacking defence on the entitlement, pause and config-write forms — which are plain form POSTs — no CSP behind the `set:html` sinks, and no HSTS. For a product serving legal-matter documents this is the largest structural gap in the tree. This is a **true absence**, not sampled absence: the search covered docs and workflows too.
3. Every agent did real work; none crashed. The three that were delivered are exactly the three that called `SendMessage`. In this session it was not.

Two more were killed by the orchestrator's own `TaskStop` while still working, on the mistaken read that "idle" meant "finished and empty." That was an orchestrator error, not a harness one, and it cost the Devil's Advocate critique of the Stage 0/1 plan.

**The cost was not hypothetical.** The undelivered Security report held both HIGH findings above, including a live auth credential reaching a datastore. The undelivered Operator report held the CRITICAL parity gap and four HIGHs. The orchestrator covered both dimensions itself and graded them B and C. It graded its own thinner sweep and did not know it.

**What is diagnostic about this**, and the reason it belongs in the report rather than a postmortem: the failure is silent and shaped exactly like success. Nothing errored. An agent went idle, the orchestrator read that as "done, nothing to say", covered the ground itself, and produced a confident report with a Security section that opened "zero exploitable findings." It is the same shape as every other finding in this review. An absent signal was read as a clean one.
