## The pattern, stated once

The runner's `llm.py` doorway, the gates, the cap, the round limits and the drop policies are code. The lanes are not "model decides everything": chunking, retries, sorting, exhibit numbering, merge falsification, audit rounds, document selection, the privilege wall, and the stop decisions are all code already (evidence per lane in the agent reports). The flaw that remains is narrower and recurs in four shapes:

1. **The model restates a fact code holds, and the restatement is what ships.** A count, a page range, a matter number, a provider name, a date already parsed by code is typed again by the model into a reply, an INDEX line or a journal row, and the typed copy is trusted. The 11-02 records replies (pp 48-49 dropped, 59 for 57) were this shape; it is still live in the post-intake record, the delivered-job replies, the chronology INDEX and FILES-SEEN blocks, and the casefile header.
2. **The model does arithmetic or date math.** Specials totals, expiry dates and weekdays, treatment-gap day counts, "not yet due", "inside 120 days", net-to-client, ledger totals, trust-floor comparisons. The gates then either trust it or refuse it (and the refusal starts a redraft loop).
3. **The model parses money and dates at the connector boundary.** Tools ask for `"1250.00"` and `YYYY-MM-DD` instead of the printed string, so a misread or a US/ISO slip is baked in before code sees it. #3729 (the 100x split-cents box) was in code, but the same class sits in the connector's tool contracts where code never sees the printed form at all.
4. **The model derives a status from events instead of reporting the events.** A defendant's status, a casefile's statute date, a discovery set's "not yet due", a negotiation offer being "joint". #3684 patched a rule table from the outside; the schema still lets the model assert the conclusion without the dated, cited events code could derive it from.

A fifth shape is cost only: **the prompt asks for output nothing reads**, or asks the model to re-emit every unchanged value so code can re-check it.

## The general things (Law 18: the second instance designs the general thing)

Most rows above are the second, third or fourth instance of a fix one lane already has. The moves cluster into six mechanisms; building each once closes a column of the table.

1. **Facts render in code, the model relays.** `records_contract.facts.render` + `reply_text` returned by the runner, and the connector's `reply_block`. Apply to: delivered-job replies (A7), the post-intake record and reply (A1), every connector filing tool's staff reply (C6). The bind refuses other words.
2. **A resolution token on every matter write.** `resolve_matter` already mints it; `stage_vendor_invoice` already requires it. Apply to every write tool in A2.
3. **As printed in, parsed in code.** Money and dates cross the tool boundary as the printed string; `howell.money` and `printed_date_candidates` parse; a figure must be found in the source text beside its label (`cited_facts.confirm`). Apply to A3, B9, and the drafting/demand figures (A4).
4. **Events in, status derived.** The model returns dated, cited events; a rule table derives the status. Apply to A6 (defendant status, `defstatus.py` is the start), B4 (statute date), B5 (not yet due), B6 (joint).
5. **Evidence-first digest.** The #3733 package (`drafting/evidence/`): extract windows, verify every excerpt on its page, tokens rendered by code, lint refuses hand-typed figures. Apply to the demand lane (A5, A4). This is the one item that is a project, not a PR.
6. **Prompts ask only for judgment.** Strip restatements, counts, sorts and dead blocks from every system prompt (C1-C4, B2, B3); strict tool schemas instead of regex over markdown (C5).
