### The #3807 gap, and its smallest fix (prototyped at $0)

The pleading the quotes came from was scanned, so its text is a machine transcription that kept the margin numbers as separate lines and dropped some of them. #3807 applies `strip_page` in `stages/extract.pdf_text` (text layer) and in the litigation text cache. It does not apply on the transcription path, and its run must be exactly 1, 2, 3 ... for at least 26 numbers. The smallest fix:

1. Accept a run that increases by 1 to 4 per step, capped at 28, with at least 20 hits (transcriptions drop numbers).
2. Apply `strip_document` where a transcribed page enters the corpus, not only in `pdf_text`.

Prototype on the same cached text: **0 of 10 defective quotes remain, and all 10 number-free forms are found verbatim**. Paragraph-number lines are unchanged (4 before, 4 after). The Q/A guard still keeps deposition transcripts out.

## Uncovered classes: the smallest code fix for each (ranked by what a firm sees)

1. **One job for two responding parties** (rows 87, 103, 106, 112, 113, 110). Sets are planned per set type, never per party, so the second defendant got nothing and a second job had to be submitted and seeded by hand. Fix: give `sets.Unit` a party. Plan units per (set type x responding party), using the request's party words matched against the matter's parties. Make the review's asked-sets check per party, and have the fixed delivery wording say which parties were served.
2. **A hand-released reply leaves the job unreplied** (row 130; fixed by hand today for 01M6PTS0). `matter_file_review approve` sends in a job's thread but never writes the job's bound claim, so after #3810 a rewake would send the attorney a second completion email. Fix: a held row can name its job (`job=drafting_job:<id>`). On approve, the broker takes the same claim `reply_binding` takes (`bound_replies` key `<kind>:<id>:<attempt>:<state>` plus the ledger's `mark_replied`), atomically with the send.
3. **No way to end a queued job** (row 139; done by hand today for 01M6PNY4). `jobs.stop` refuses a job with no job dir, and `Daemon.claim_next` never reads the ledger row's state, so a row marked failed still runs once its lane is proven. Fix: `jobs.stop` on a queued job claims it into its job dir with `daemon.json` `stopped_by_smd` and records failed through the broker (the shape `smd_stop.finish` writes). `claim_next` also skips an envelope whose ledger row is terminal.
4. **Margin numbers from scanned pleadings** (row 123): the #3807 extension above.
5. **A signal-killed job records $0 spent** (rows 62, 79; measured here). `drafting_lane._report` takes cents from the verdict, and a no-verdict exit has none (`drafting_lane.py:254-257`): 01M6M7FQ spent $2.22 and 01M6MGAA $7.07, and both rows read 0. So the month's allowance undercounts. Fix: on `no_verdict`, record `smd_stop.spend_cents(job_dir)`. Separately, a child killed by a fleet release is recorded failed instead of left claimed for the next boot, which is how two revision jobs died without a word. That needs the release's quiesce to count as a stop in `resume.cut_short_by_stop`: not proven here, so read that path before changing it.
6. **A held job's requester is told "I'll reply when it's filed"** (row 135, also 46 and 70). A `lane_unproven` hold, or a job that died, gives the requester no word, and the model's own status replies were false twice (rows 70, 90). Fix: the submit result of a held job, and the failed-state wake, carry a fixed wording ("this is waiting for SMD; you will hear from us") that the reply must use, the same mechanism as #3810.

Not code-fixable in this key (the Captain's call or another lane): no section class for a stand-alone brief section (row 134; memo was the wrong class); revision requests ran as fresh full jobs (rows 48, 59, 78; the revise route exists but `revise_mediation_brief` is unproven on the seat); the rule-store rows (60, 69 to 71, 74, 77, 85, 131, 132); and firm layout coming from SMD's renderer (52, 65, 83).
