## The six mechanisms (what gets built once)

1. **Outcome ledger, journal from outcomes.** A keying act writes its own outcome row; the post record is derived from those rows and from what the letter's kind requires, never typed.
2. **Resolution token on every write that targets a matter the model chose.** Declared once in the SDK with a per-tool matter resolver; shipped observe-first; code callers unchanged.
3. **As printed in, parsed in code, confirmed in the source.** One money parser and one date parser for every connector tool; a figure must be printed in the document it came from.
4. **Fixed wording, rendered by the broker at bind time.** A job's reply words, held or delivered, are rendered by code from the ledger row and the broker's own reads when the model binds; templates carry zero slots; the broker refuses other words at send.
5. **Conflict check is a tool whose result the trust gate enforces on writes and sends.** Code matches names and roles under a written rule table; the gate refuses writes and sends in a conflict-possible turn with no recorded `clear`, and everything on a `hit`.
6. **Events in, status out; prompts ask only for judgment.** Dated, cited events from the model; rule tables derive status; restatements, counts and dead blocks leave every prompt.
