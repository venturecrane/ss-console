# Firm documents: one answer to file, style, reader and correction

Design, 2026-11-06, revision 4. Step 3 of the document-library work. Built on `research-map-2026-11-06.md` (same folder) and governed by ADR 0083, which this design implements and does not reopen. Revision 2 folded in the coordinator's rulings and an independent critique; the last section lists what changed and what was not adopted. Revision 3 removes every paid proving run on the Captain's direction: each piece is proven at no model cost, and the live proof is the first real request, read back by code.

## What a firm experiences

**Every document starts in the firm's own Word file.** The firm has one place, its Document Library, holding one Word file per kind of document: letter, memo, demand letter, mediation brief, discovery set, discovery response, deposition outline, and its forms. Whatever the firm asks the Operator to draft, the Operator opens that kind's file and writes into it. There is no second copy anywhere the firm cannot see.

**The file is the firm's, taken from a document the firm already made.** An administrator says "set up our mediation briefs". The Operator finds the firm's own finished documents of that kind, names the best candidates by file, and asks which to use. On the administrator's yes it makes the library file from that document, with every word of the case removed and all of its look kept. A kind that is not set up yet is drafted on a plain base, and the library's status says which kinds are still plain. A kind the firm already receives in a layout it wrote down or accepted keeps that layout exactly; nothing a firm has today gets plainer.

**An attorney can have their own.** If an attorney's documents of a kind look different from the firm's, the same request ("set up Dana's demand letters") makes that attorney's file beside the firm's. A draft uses the file of the attorney whose name goes on the document, read from the matter; the person asking can name a different attorney on the firm's roster. An attorney with no file of their own gets the firm's, and nothing in the document or the reply remarks on it.

**It reads the way the firm writes, for the person who will read it.** Each kind has a known reader: an adjuster for a demand, a mediator for a mediation brief, opposing counsel for discovery, the attorney for a memo or a deposition outline, and for a letter whoever it is addressed to. The Operator writes for that reader in the firm's way of writing. Papers served under court rules are written in the plain register the rules call for. Where an attorney's own documents measurably differ in wording from the firm's, that is layered on for documents in their name; where they do not, it is not invented.

**Edit the look in Word and the next draft follows.** Change a font, a margin, a heading, the letterhead or the spacing in the library file, save it, and the next draft of that kind has it. Nobody at SMD does anything.

**Say it once.** "Double space the headings", "never cite the medical records in a brief", "Dana's demands close with Cordially": the Operator reads the rule back in the firm's words, stating exactly which kind of document and whose, and on a yes it holds from the next draft on. The Operator never answers that a rule was recorded but is not in effect for a kind of document it drafts.

**When they disagree, the order is fixed.** What a court rule requires comes first. Between a rule the firm said and a change the firm made in its file, the later one wins, because both are the firm's own word. A rule is never silently undone and an edit is never silently ignored: when a later edit changes something a rule set, the rule is shown as replaced by that edit, with the date, where the firm can see it.

## How it is built

**One resolver, two callers.** Every path that produces a document, a chat turn's document tool or a queued job, calls one piece of code before it writes, with the matter, the kind, who asked and any attorney they named. It answers four questions: which Word file, whose name and style, which reader, which rules. It writes its answers beside the filed document, and that record is what every later check and the Operator's own reply read. A test fails the build when a document-producing path does not call it, and a second test fails when a path calls it and then starts from anything else.

**The library is read through a small interface, not a case system.** Four calls: find the file for a kind, list its versions, fetch one, file a new version. The resolver is plain code with no case-system import, kept in the connector toolkit both the document tool and the jobs runner already install (`operator/connectors/_sdk`, `runners/jobs/pyproject.toml:41`). Today's case-system connector is the first implementation. A firm on another case system, or with none, is a second implementation and no redesign. No second implementation is built now.

**A file is used only once it is accepted, and the seat keeps the list and the file.** The seat holds a ledger of accepted library files: kind, attorney if any, file, version, fingerprint, and whose yes made it so. Only code writes it. Beside the ledger the seat keeps its own copy of each accepted file, root-owned and named by fingerprint, installed the same way the firm's rules are. A document is made from that copy. The case system is asked only whether a newer version exists: it can hand back a file's current version and nothing earlier, and it cannot say who saved it. The kept copy is a blanked form and holds no client text; a test asserts that on the bytes. It is a new runtime layer and is listed in CLAUDE.md's removal inventory with its path, its prune rule and the command that purges one firm. This replaces today's pinned copies in the firm's private inputs without losing what the pin gave, and it settles which file is the firm's: the starter files our setup filed are not accepted files, so no kind moves onto one.

**A firm's own edit to its file is the firm's word, and code accepts it on the spot.** When a job finds a newer version that the ledger did not write, it is the firm's own edit. Code fetches it and checks that it can still be written into: the fixed words and the marked places are intact. If it passes, it becomes the accepted copy for the very draft being made and is recorded in the ledger as firm-made, with its date. No administrator approval and no SMD step: asking for a second yes would break the promise. If it fails the check, the draft is made in the previous accepted copy and SMD is paged. Whether the reply then tells the firm its edit was not used is a switch, off until the Captain decides.

**Two kinds of library file, named as such.** A styles file (page setup, header and footer, named styles; the body is written fresh) is what ADR 0083's 2026-08-19 amendment describes. A marked file (the firm's own document with its words replaced by marked places, so captions, signature blocks and tables keep their exact look) is what the firm-base code makes. The resolver returns the file and which kind it is. Marked places are read from a paragraph's whole text, so a save in Word that splits the text does not break them; this is tested against files actually saved by Word. The ADR gets an amendment naming the second kind.

**Reused, as is or nearly:**

- The library folder and its lookup, which fetches fresh on every use (`library.py:505-555`).
- The firm forms path, unchanged. It is the model.
- The demand lane's whole writer and format check, unchanged. It delivers a format the firm accepted. It gains only this: its reference files move into the library and it gets them, the attorney and the rules from the resolver.
- The choice of attorney from the matter in code (`demand/run.py:576-599`), lifted into the resolver.
- The firm-base layer that writes into a firm's own file and proves nothing was lost (`firmbase/`), its two existing per-kind plans (brief, memo), and the read-only hunt (`firmbase/hunt.py`). They get their missing caller.
- The say-it, read-it-back, yes flow and the seat store it writes to (`establish_propose`, the spec applier), which the drafting job already reads for layout.
- The voice work already done: the firm voice established on the client seat, the adjuster profile in the demand inputs, the court and internal profiles of 09-08, and the four checking tools in `operator/bin/`, which become the instrument for proving a draft reads as its profile says.

**Unified:**

- **Which Word file:** four answers become one, the accepted library file for the kind or the attorney.
- **Layout:** one order of precedence (court rule, then the later of the firm's rule and the firm's own edit to its file) replaces three unranked sources. A rule is applied into the library file as a new version and recorded in the ledger as written by code. Any version the ledger did not write is the firm's own edit: the case system's history cannot tell a person's save from the Operator's (it shows the same user for both), so the ledger is what tells them apart. If a later firm edit changes a property a rule set, the rule is marked replaced by that edit. If the ledger cannot place a version, the rule stands and SMD is paged. The drafting job's typed layout keys retire kind by kind, each only after a library file carrying the same layout exists and a saved draft measures the same through the new path as through the old.
- **Wording:** the drafting job's one style file, the demand job's voice files and the installed voice file become one store, keyed from the start by kind, attorney and reader, read by every path through the resolver. Three layers, each with its own source. The firm's base is the firm voice established from the firm's own documents. A reader's profile is what already exists for that reader. An attorney's layer is what that attorney has said: instructions an attorney gave are rules scoped to that attorney, applied when the document carries their name, and they never become the firm's base by default. Format rules among an attorney's instructions that are really the firm's look for a kind (font, spacing, paper) live in the accepted file for the kind and so reach everyone.
- **The one seat with drafting live is the case this corrects.** Its firm-wide style file is one attorney's own written instructions, sent by the firm as his, and today it is applied to every drafting request whoever's name is on the document. In the store those instructions are scoped to him. The move changes nothing for a request in his name: what a job sends the model is compared before and after and must be identical. For a request in another attorney's name what is sent will differ, and the exact difference is listed for the Captain before any seat is switched on. Thirteen drafting jobs have run there, nine from him and four from SMD, so no other attorney's document changes in practice yet.
- **Who an attorney is:** one roster entry per attorney, read by forms, demands, captions and signatures.
- **Kinds of document:** one registry stating each kind's reader, variant and producing path. The other lists are pinned to it by test.

**Removed:**

- The retired sample-transform voice mechanism, from the tree and from all seven seats that configure it, with a probe of each runtime layer on each (ADR 0083 decision 6).
- The drafting job's typed layout keys and pinned base, and the demand job's private voice and reference files, each in the piece that gives its content a home, under the no-change measure above.
- The audience list block nothing reads, and the outline text setup writes into library files.
- The "recorded, but not yet in effect" reply for every kind of document a job drafts. It stays, because it stays true, for record products (chronologies, workbooks) that read no rules.

**Held lines:**

- **No kind refuses for want of setup**, but a store or ledger the seat cannot read is not "unset": that job holds for SMD, as ADR 0083's 2026-08-10 amendment requires.
- **A rule's reach is never widened by the Operator.** Without explicit words it covers the kind and attorney of the request it answers.
- **A rule that can be checked is checked in code** ("never cite the medical records" becomes a check on the finished document, as the citation policy already is), not left to prompt wording.
- **Setting up a kind is a queued job, never a chat turn**: it reads across many matters.
- **A file made from a client's document proves it carries none of that client**: the proof lists what may remain, and refuses anything else.
- **An attorney not on the roster cannot be signed for.** That request holds and says so; it is identity, not style.

## What is not yet known

- **Measured, 11-06: whether this firm's attorneys differ in look and in wording** (8 most recent finished documents per signing attorney, attributed by signature block and never by who typed the file, with chance tests and same-attorney controls; read-only, no model cost). Mediation briefs: no attorney difference in look (0 of 48 properties differ between attorneys while each attorney is consistent), and a brief's look is not stable even within one attorney, whose newest eight differ from his previous eight about as much as two attorneys differ; each brief appears to take its look from whichever earlier file it was started from. Demand letters: one attorney's differ from everyone's in look and the other current attorneys share one look (8 of 50 properties, controls 0). Wording: not shown by this tool on 8 files, for either kind, among current attorneys. That is not a finding that they write the same: the tool could not tell one attorney's briefs from the same attorney's demands. Discovery and letters have enough signed files per attorney to measure when a difference is claimed. Deposition outlines cannot be attributed: 1 of 63 carries a signature block.
- **What the firm has actually used and corrected** now orders the kinds in piece 6: discovery sets first (7 of 13 drafting jobs), then responses, letters, deposition outlines. Its 11 corrections were 6 about look and 5 about wording, which is what pieces 1 and 5 serve. Its two "write it like this attorney" asks went to SMD by email, which is what pieces 3 and 8 serve.
- **Which steps of a lane cannot be rehearsed without a model.** Piece 0 lists them by name once the pilot can be read; each waits for a real request.
- **Whether a letter's addressee can be told apart as opposing counsel or vendor in code.** Insurer, adjuster and client can: the forms path already reads them from the matter's own contact roles (`form_letters.py:206,245,288`).
- **The read route to the pilot seat.** The laptop probe was refused by the permission system for this session and for the coordinator; it is with the Captain as a permission request.

## What changed in revision 2, and what was not adopted

Changed, with the source:

1. **Layout has an order of precedence, not a single source** (critique, amended by the coordinator). "The file is the only source" would have made the format check compare a file with itself and let a Word edit silently undo a rule the firm said once. The coordinator's amendment: between the firm's rule and the firm's later edit, the later wins, and neither is silent.
2. **An accepted-file ledger on the seat** (critique). A library file anyone can edit, picked by newest name, has none of the integrity today's pinned copies have.
3. **A proving seat first** (critique). Staging authors no case system and the pilot has proven no job lane, so the old plan's first seat would have been the client's.
4. **The demand writer is kept** (critique, against the coordinator's parity-then-replace ruling). The firm-base layer is already the general part; what differs per kind is its plan, and demand's key is kind by variant by attorney. Replacing the one lane with seven clean deliveries buys the firm nothing.
5. **Marked places survive a save in Word, and the two kinds of library file are named** (critique).
6. **Two callers, a stated interface, no case-system import** (critique and coordinator ruling B).
7. **Rules take effect first** (critique). It is what the answer key's rows show the firm actually ran into, and it needs nothing from the library.
8. **No kind's layout may regress** (coordinator ruling A): the measure-the-same gate on pieces 2 and 5.
9. **The "your edit was not used" sentence is a switch, off** (coordinator ruling 2).
10. **Proofs that could not fail were replaced** (critique): round trips, pre-written traits scored by tools, and a guard that checks the path used what the resolver returned.
11. **Seven seats, not two**, configure the retired mechanism.
12. **The seat keeps its own copy of each accepted file** (the resolver's builder, revision 4): the case system cannot fetch an earlier version or say who saved one. A firm's own edit is accepted by code for the draft being made, with no one's yes (coordinator).
13. **An attorney's instructions are scoped to that attorney** (coordinator, revision 4), and the store carries kind, attorney and reader from the start. The measurement of 11-06 is recorded under what is known.
14. **No paid proving runs** (the Captain, 11-06, revision 3). Five capped runs on the pilot were proposed and withdrawn. Every proof is at no model cost, and the read-back of the first real request is built into the code as piece 10.

Not adopted:

- **Deferring the plain letter until a firm asks** (critique). The acceptance test names seven kinds and the coordinator ruled a letter needs a Word path. It is last among the kinds.
- **Dropping the reader and attorney pieces as ahead of the evidence** (critique). The Captain asked for both by name. What is adopted is the critique's discipline: existing profiles first at no cost, and an attorney's wording only where a measured difference exists.
- **A kind for "a section of a brief", and revisions that run as fresh jobs** (critique, answer key rows 134, 48, 59, 78). Real, and outside this fixed list; they go on the Captain's list.
