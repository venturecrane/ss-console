# Discovery Response Staging - Output Format

The decision determines the shape. Every staging action is keyed to the matter and the
response-set it serves. No shape ever contains a discovery-response draft; the drafting
engine authors that, not this skill.

## Shape A - Staged (inputs placed in the confirmed target, writes confirmed)

```markdown
# Staged - <matter descriptor> - <response-set> - matter <id> - YYYY-MM-DD

**Decision:** staged the request and supporting docs into <confirmed input folder>; each write confirmed by a follow-up read.
**Staging target:** <folder> (from the authored convention / config mapping for <engine>)
**Placed (each confirmed present via get_files_on_matter):**

- served request: <file>
- supporting: <prior verified responses / records - each named, each read from the matter>

## Internal note to <responsible attorney / paralegal>

> The inputs for the <response-set> response are staged in <folder>. Ready for <engine> to draft.

## File note (create_memo)

[Operator] <Routine name> as of <localDate>
Staged <N> inputs for <response set> into <folder>; each one confirmed in the matter. The draft is generated by <engine>, not here.
Nothing to do until the draft comes back.
```

## Shape B - Returned draft routed to the attorney

```markdown
# Draft routed - <matter descriptor> - <response-set> - matter <id> - YYYY-MM-DD

**Decision:** finished draft observed in the matter; left in place and routed to <responsible attorney> to review. Not moved, not edited, not finalized.
**Draft:** <file> (observed via get_files_on_matter; identified by diffing against the staged input set)
**Routed via:** create_task assigned to <personResponsibleStaffId>, keyed to <matter>/<response-set>, **confirmed present via list_tasks/get_task**. dueDateOnly = <near-term confirm-by date, distinct from any legal deadline>.

## File note (create_memo)

[Operator] <Routine name> as of <localDate>
<Response set> draft found in the matter and a review task set for <attorney>; the draft was not moved or edited.
<Attorney> to review the draft.
```

## Shape C - Surface to a human (target/convention unknown, write unconfirmed, ambiguous candidate)

```markdown
# ⚠ Staging - needs a human - <matter descriptor> - matter <id> - YYYY-MM-DD

**Situation:** <staging target / folder convention not established - proposing <candidate> to confirm | a write did not confirm (add_file/create_folder/create_task/create_memo error or no confirming-read match) | draft present in the matter but the review task could not be confirmed created | returned-draft candidate cannot be matched to the response-set with confidence>
**Decision:** surfaced for a person. Nothing asserted as staged or routed. This is a judgment the skill does not make on its own.
**Proposed (if applicable):** stage into <candidate folder> - confirm this is where <engine> draws from before I write.
```

## Rules

1. **No shape contains a discovery-response draft.** The skill stages inputs and routes
   outputs; it never authors the response (floor `discovery-response-staging-no-drafting`).
2. **Shape A is reachable only when the target folder is confirmed AND every write is
   confirmed by a follow-up read.** An unconfirmed target or an unconfirmed write is
   Shape C, never Shape A.
3. **A folder name is never stated as a fact in Shape A unless it came from the authored
   convention / config mapping.** A guessed target belongs in Shape C as a proposal to
   confirm, never as a completed placement.
4. **A returned draft is routed (Shape B), never finalized.** The skill does not edit,
   complete, or mark a draft final; the attorney reviews and finalizes.
5. **Shape B is reachable only when the review task is confirmed by a read.** A
   `create_task` call that returned but was not confirmed via `list_tasks` / `get_task`
   is Shape C ("draft present, review task not confirmed"), never Shape B. Routing is
   in-place: the task points at the draft where it sits; the draft is never moved.
6. The decision and its reason are always stated, so the placement and the routing are
   auditable.
